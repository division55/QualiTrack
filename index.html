Methodology & Rubric

What QualiTrack measures

QualiTrack retrieves observable metrics from the GitHub public API and maps them to four quality dimensions defined in ISO/IEC 25010: Maintainability, Reliability, Community Health, and Documentation & Standards. Each dimension contributes a weighted sub-score to a final score out of 100.

Note: This is an educational assessment tool. Metrics like test coverage and static analysis results are not available through the public API and are excluded. Where excluded, limitations are flagged in the output.

Scoring Rubric

DimensionWeightSignals
Maintainability30Commit cadence, recency, release count
Reliability25Issue resolution ratio, open/closed
Community Health25Stars, forks, contributor proxy
Documentation20License, wiki, description, topics

SE Concepts Demonstrated

  • Requirements Engineering — functional and non-functional requirements defined before build
  • Software Design — modular architecture: API layer, scoring engine, UI layer
  • SQA — ISO 25010 quality model, custom weighted rubric
  • Testing — input validation, API error handling, edge cases
  • Maintenance — recommendations engine flags weaknesses
  • Process Improvement — every recommendation is tied to a specific triggering metric

Data Sources & Limitations

  • GitHub REST API v3 (public, no auth for basic endpoints)
  • Rate limit: 60 requests/hour unauthenticated
  • Test coverage % — not available via API; requires Codecov/CI integration
  • Static analysis (cyclomatic complexity, code smells) — not available; requires local tooling
  • Security vulnerability count — not exposed in public API
